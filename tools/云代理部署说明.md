# 云代理部署说明

> 配套文件：`cloud_proxy.py`（云函数源码，纯 Python 标准库，无需打包依赖）
>
> 本文按「从零部署 → 验证 → 接进定时抓取与页面手动更新」的顺序编排。控制台字段可能随平台版本调整，**以页面实际显示为准**。

---

## 一、这个云函数用来做什么

它是**彩票官方接口的境内转发通道**，给 GitHub Actions 的定时抓取工作流用，也给页面「手动更新」里的福彩请求做跨域转发。

定时工作流的 runner 出口 IP 在境外，彩票站按 IP 段风控，直接抓会返回 403 / 567，退避重试也无效。工作流把每个官方请求改写成：

```
<云函数地址>?url=<URL 编码后的官方接口地址>
```

云函数在境内出口代为请求官方接口，把原文返回给抓取脚本。脚本再与仓库已有数据合并、重新生成页面、自动发布到 GitHub Pages。

| 环节 | 位置 | 说明 |
|---|---|---|
| 官方接口 | 中国福彩网 / 中国体彩 | 双色球、福彩3D、大乐透、排列三 |
| 转发 | 境内云函数（本文件部署的） | 出口 IP 在境内，不被按段风控 |
| 调用方 | GitHub Actions 定时工作流 | 一天 1~2 次，每次只抓增量 |
| 最终用户 | 浏览器打开 Pages 页面 | 数据已烤进页面，**不需要知道这个地址** |

四彩种的抓取请求统一走这条通道。福彩接口不返回任何 CORS 头、也不支持 JSONP，若以后要在浏览器里直连福彩接口，同样可以经本函数转发（体彩接口自带 `access-control-allow-origin: *`，可不走代理）。

**页面里没有代理配置入口，普通用户也不需要配置任何东西。** 地址只存在仓库的 Secret 里，构建期注入。

### 为什么不能部署到 Render / Vercel / onrender

这些平台的出口 IP 在**境外**，与 GitHub Actions 是同一类问题。转发必须放在**境内云**，出口走境内 IP。

### 这套代理解决什么、不解决什么

- 解决：境外 runner 被彩票站按段风控（403 / 567）
- 解决：福彩接口不开放跨域时的浏览器直连（如以后需要）
- **不解决**：彩票站自身的限流。工作流一天只跑 1~2 次且只抓增量；若遇限流，等下一次定时运行即可，不要手动高频重跑
- **不涉及**：开奖预测、中奖概率、金额记账

## 二、腾讯云 SCF（推荐，逐屏对照）

控制台网址：**https://console.cloud.tencent.com/scf**

首次使用若提示「服务授权」，按页面引导点一下授权即可。

### 2.1 基础配置页

| 字段 | 填什么 |
|---|---|
| 创建方式 | 「从头开始」 |
| **函数类型** | **事件函数**（不要选 Web 函数） |
| 函数名称 | 自定义，例如 `lottery-proxy`；只能用字母、数字、连字符，2~60 字符 |
| 地域 | 境内任选（广州 / 上海 / 北京都行） |
| **运行环境** | **Python 3.10** |
| 时区 | 保持默认 |
| 提交方法 | **在线编辑** |
| **执行方法** | **`index.main_handler`** |
| 代码文件 | `index.py` |

**为什么必须是事件函数**：腾讯云官方文档说明，Web 函数的函数 URL 会把 HTTP 请求直接透传、不做 event 格式转换；而 `cloud_proxy.py` 读的是 event 里的 `httpMethod`、`queryString` 等字段，只有事件函数才会生成这些字段。选 Web 函数会取不到参数。

### 2.2 高级配置 / 环境配置

| 字段 | 填什么 |
|---|---|
| 命名空间 | `default`，不用改 |
| 描述 | 可留空 |
| 资源类型 | CPU |
| 内存 | **128 MB**（够用；调高只会增加费用） |
| 临时存储 | 0.5 GB（页面注明该规格免费，超出按量计费） |
| 初始化超时时间 | 保持默认 |
| **执行超时时间** | **改成 30 秒**（默认 3 秒） |
| 环境变量 | 不用填 |

> 源码用 `urllib.request.urlopen(..., timeout=20)` 请求上游，接口偶尔响应慢。执行超时保留默认的 3 秒会直接超时，表现为「上游请求失败」。30 秒留出余量。

### 2.3 权限 / 层 / 插件 / 网络配置

| 字段 | 填什么 |
|---|---|
| 运行角色 | 不启用 |
| 层 | 不添加（源码只用标准库，零依赖） |
| 插件配置 | 不启用（128 MB 规格本来也不支持） |
| **公网访问** | **保持勾选启用**（关了函数就访问不到福彩官网） |
| 固定公网出口 IP | **不要勾**（页面提示开启后平台侧无法横向扩展；本项目不需要固定 IP） |
| 私有网络 | 不启用 |
| 固定内网出口 IP | 不启用 |

### 2.4 执行配置 / 并发 / DNS / 标签

这一屏**全部保持默认、一个都不要启用**：

- 文件系统：不用加
- **异步执行**：不要勾。勾了函数变成异步调用，浏览器拿不到同步响应
- 状态追踪、应用性能观测：不启用
- 并发配置（最大独占配额）：留空
- 请求缓冲 / 最大缓冲时间：不启用
- DNS 缓存：不启用
- 标签：不启用

### 2.5 触发器配置 —— 这一步是关键

**保持「暂不创建」**，不要点「自定义创建」去找 API 网关触发器。

原因：腾讯云《API 网关触发器功能下线通知》写明，2024-07-01 起新老用户不再支持新建 API 网关触发器，API 网关产品 2025-06-30 停服，基础功能建议改用**函数 URL**。新建页「触发器配置」区域那段橙色提示说的就是这件事。

函数 URL 和触发器是**同级**的两个能力，不在「触发器」里：函数建好后，从**函数详情页左侧导航「函数 URL」→ 新建函数 URL** 进入。

函数 URL 的端点格式：

```
https://<app-id>-<url-id>.<region>.tencentscf.com
```

### 2.6 粘贴代码并部署

在新建页的「函数代码」区域（或建好后进函数详情 → **函数代码** 页签）：

1. 提交方法：**在线编辑**
2. 文件名保持 **`index.py`**
3. 把 `cloud_proxy.py` **全文**复制进去（从 `# -*- coding: utf-8 -*-` 到最后一行）
4. 点 **部署**

源码里写了三个入口别名：`main_handler`（腾讯云）、`handler`（阿里云）、`lambda_handler`（华为云 / Lambda）。执行方法填 `index.main_handler`，与上面基础配置一致。

### 2.7 创建函数 URL（逐字段）

控制台路径：**函数服务 → 单击函数名进入函数详情 → 左侧导航选「函数 URL」→ 单击「新建函数 URL」**。函数 URL 默认关闭，必须手动新建一次。

#### 推荐配置：CORS 保持「未启用」

| 字段 | 怎么填 | 说明 |
|---|---|---|
| 别名 / 版本 | 保持「默认流量」 | URL 与别名/版本一对一绑定，每个别名/版本仅允许一个 URL；以后换版本要为新版本再开一次 |
| 公网访问 | **启用** | 不勾浏览器访问不到。旁边橙色「仅供测试使用的免责说明」是腾讯云对该能力的定位标注：官方把函数 URL 公网访问定位为测试用途，个人低频查开奖数据够用；若要长期对外提供服务，按官方指引另配自定义域名（中国大陆需先备案） |
| 内网访问 | 不启用 | 浏览器从公网来，用不上 |
| **CORS** | **不启用** | **推荐**。跨域由云函数代码自己解决：`_ok()` 给每个响应都带 `Access-Control-Allow-Origin: *`、`Access-Control-Allow-Methods: GET, OPTIONS`、`Access-Control-Allow-Headers: *`，`main_handler` 也处理了 `OPTIONS` 预检。不启用控制台这层 CORS，就不会提交 `CorsConfig`，也不会出现两层响应头重复 |
| **授权类型** | **开放** | 页面原文：「SCF 不会对您的函数 URL 的请求执行身份验证……URL 端点将是公开的，可能会导致预期之外的请求来源触发访问，为保障服务安全，建议您在使用函数 URL 时开启 CAM 鉴权」。本项目必须选开放，否则普通用户无法匿名更新；代价与防线见第八节 |
| 参数兼容 | **建议关闭**；保持开启也能用 | 页面原文：「若您从 API 网关迁移至函数 URL，需保持原请求参数格式，请开启参数兼容模式（函数将自动处理请求参数，部分 API 网关特有字段留空，Base64 特性暂不支持）」。从零新建不需要兼容旧格式；开启时源码 `_q()` 也能取到参数，见 2.8 |
| 确定 | 点确定 | 创建后复制列表里的端点 |

#### 如果选择启用 CORS

启用后弹窗会展开一组字段，这几项必须动手改（默认值不完整）：

| 字段 | 填什么 | 说明 |
|---|---|---|
| **Allow-Origin** | **`*`** | 页面原文：「添加可以访问函数 URL 的源……可以使用通配符(*)授予对所有源的访问权限，多个 Origin 之间用英文逗号隔开」。**留空等于没放行任何源**，浏览器会报 CORS 错。想收紧可填站点域名，但**本地双击打开的单文件版是 `file://`、Origin 为 null，会被拒**，所以建议用 `*` |
| **Allow-Methods** | 勾 **`GET`**（或最左 `*`） | 前端只用 GET（`?lot=`、`?url=`）。**一项不勾预检过不去**；若后续预检仍失败，改勾 `GET` + `OPTIONS` 再试 |
| Allow-Headers | `*` 或留空 | 页面原文：「允许所有 Header 则填*」。前端没有自定义请求头 |
| **Expose-Headers** | **`*`**（不要留空） | 页面原文：「请输入允许暴露给 XMLHttpRequest 对象的 Header……允许所有 Header 则填*」。**留空提交会被平台拒绝**，返回 `InvalidParameterValue.Cors` / `(Invalid ExposeHeaders: )`，冒号后为空正对应这个空输入框。前端取的数据在响应体里，本来也不需要 `Access-Control-Expose-Headers` |
| Allow-Credentials | 不勾 | 不用凭证；且 Allow-Origin 为 `*` 时浏览器不允许带凭证 |
| Max-Age | 600（可选，默认 5 也能用） | 浏览器缓存预检结果的最长时间，调大可减少预检次数 |

腾讯云《创建函数 URL》的 API 参数表里，`CorsConfig` 结构为：

```json
{"Enable": true, "Origins": ["*"], "Headers": ["content-type", "custom-header"],
 "Methods": ["POST", "PATCH"], "ExposeHeaders": ["*"], "MaxAge": 10, "Credentials": true}
```

其中 `Origins` 标注为**必选**，描述为「对于不需要携带身份凭证的请求，服务器可以指定该字段的值为通配符 `*`，表示允许来自任意源的请求」；授权类型 `AuthType` 中 `NONE` 表示无需授权（对应控制台「开放」），`CAM` 表示需鉴权。

**两层 CORS 并存的处理**：控制台这层与代码返回的头都可能生效。若浏览器控制台报「`Access-Control-Allow-Origin` 头重复 / contains multiple values」，把控制台这层 CORS 关掉，只留代码返回的头——代码自己会处理预检，关掉不影响功能。以实际响应头为准。

### 2.8 事件结构与取参（不用改代码）

腾讯云《函数 URL 概述》给出的**事件函数** event 示例：

```json
{
  "body": "{\"test\":\"hello world\"}",
  "headers": { "accept": "*/*" },
  "httpMethod": "POST",
  "path": "/",
  "queryString": { "a": "1", "b": "2" }
}
```

该文档注明，函数 URL 事件兼容 apigw 协议，但**去掉** `headerParameters`、`isBase64Encoded`、`pathParameters`、`queryStringParameters`、`requestContext` 等字段。也就是说，默认（未开「参数兼容」）下查询参数只在 `queryString` 里；开启参数兼容后会补齐部分 apigw 字段。

`cloud_proxy.py` 的 `_q()` 把 `queryString` 放在首位，并跳过列表里的空值，两种结构都能取到参数：

```python
q = (event.get("queryString") or event.get("queryStringParameters")
     or event.get("queryParameters") or {})
```

`httpMethod` 字段同样存在，所以 `OPTIONS` 预检能被正确识别。响应负载按 `{statusCode, headers, body}` 返回，同时带上 `isBase64Encoded: False`：函数 URL 标准负载不使用该字段，而参数兼容模式下网关若按 API 网关集成响应格式解析，该字段是必需的，带上两边都能通过。

### 2.9 拿到地址并验证

复制函数 URL 列表里的端点，形如：

```
https://125xxxxxxx-abcdefgh.ap-guangzhou.tencentscf.com
```

**① 根路径自检**（不带任何参数）：

```json
{"ok":true,"service":"lottery-proxy","hint":"用法：?lot=ssq&n=3 或 ?url=<白名单内的彩票官方地址>","lots":["ssq","3d","dlt","pls"]}
```

看到这段 = 请求已到达函数、执行方法 `index.main_handler` 被正确调用、部署的是含自检逻辑的源码。**看不到 = 请求没到达函数或部署的是旧版代码**，按第六节的方法定位，先别改配置。

**② 便捷入口**：

```
https://你的地址/?lot=ssq&n=3
```

应返回一大段 JSON，含 `"name":"双色球"` 和当期 `"code"` 字段（期号是当天最新，不是固定值）。

**③ 云端抓取工作流实际走的分支**（这条一定要测，CI 用的是它）：

抓取脚本对福彩拼的是 `<代理地址>?url=<URL 编码后的福彩官方接口地址>`，完整拼法模板：

```
https://你的地址/?url=https%3A%2F%2Fwww.cwl.gov.cn%2Fcwl_admin%2Ffront%2Fcwlkj%2Fsearch%2Fkjxx%2FfindDrawNotice%3Fname%3Dssq%26issueCount%3D3
```

应返回同样的福彩 JSON 原文。体彩同理，把 `url` 换成 `webapi.sporttery.cn` 的官方接口地址即可。

**④ 诊断端点**（参数落在哪个字段里，不用猜，也无需配置日志）：

```
https://你的地址/?diag=1
```

返回 `event_keys`、`httpMethod`、`queryString`、`hasQueryStringParameters`、`path` 等字段。

## 四、把地址接进 GitHub 仓库

地址有两个用途，配置点各自独立：

**一、云端定时抓取（主链路）** —— 仓库 Secret `LOTTERY_PROXY`。

1. 打开仓库 → **Settings** → **Secrets and variables** → **Actions**
2. 点 **New repository secret**
3. Name 填 `LOTTERY_PROXY`，Secret 填函数 URL 地址（形如 `https://125xxxxxxx-abcdefgh.ap-guangzhou.tencentscf.com`）
4. 保存

`refresh-data.yml` 已写好注入：

```yaml
env:
  LOTTERY_PROXY: ${{ secrets.LOTTERY_PROXY }}
```

| 用途 | 文件 | 行为 |
|---|---|---|
| 抓取转发 | `crawler.py` | 所有官方请求改成 `<地址>?url=<官方地址>` |
| 构建期内置 | `build_single.py` / `build_static.py` | 把地址写成产物里的 `PX_BUILTIN` 常量，作为页面手动更新的兜底来源 |

**二、页面手动更新（补充链路）** —— 管理员在页面里配置，普通用户自动生效。

1. 管理员登录 → 菜单「数据更新」→ 面板底部「云代理地址」填同一个函数 URL → 保存到本机
2. 点「导出站点配置」下载 `proxy.json`
3. 把 `proxy.json` 放到**站点根目录**（与 `index.html` 同级）并提交

之后普通用户启动页面时会自动读取该配置，直接点「全部更新」即可更新双色球 / 福彩3D；他们看不到输入框。页面取地址的优先级是 **本机（管理员）> 站点 `proxy.json` > 构建期内置**。不配置也不影响正常阅读，只是福彩的手动更新不可用。

### 地址格式（最容易填错）

```
✅ 正确：https://125xxxxxxx-abcdefgh.ap-guangzhou.tencentscf.com
❌ 错误：https://125xxxxxxx-abcdefgh.ap-guangzhou.tencentscf.com?url=
❌ 错误：https://service-xxx.gz.apigw.tencentcs.com/release/xxx（API 网关域名，已停用）
```

**末尾不要带 `?url=`**。抓取脚本会自己拼 `?url=<目标地址>`；多写一个就变成两个 url 参数，后端取到第一个空值会失败（源码已做空值跳过兜底，但按正确格式填更稳妥）。

### 本地构建时怎么内置

CI 会自动注入。若在自己电脑上重建单文件版并希望产物带上这个常量：

- 双击 **`设置云代理并重建.bat`**，粘贴地址，脚本自动重新生成
- 或命令行：`python build_single.py --proxy=你的地址`，也可设环境变量 `LOTTERY_PROXY` 后直接运行
- 清除内置：`python build_single.py --proxy=off`

### 范围提醒

普通用户看不到也改不了地址；只有管理员登录后能填写与导出。换地址时两处都要更新：改 Secret 影响下一次定时抓取，重新导出 `proxy.json` 影响页面手动更新。只改一处会出现「定时抓取正常但页面手动更新仍指向旧地址」的情况。

## 五、验证是否生效

| 方法 | 操作 | 成功标志 |
|---|---|---|
| 根路径自检 | 地址栏直接打开不带参数的地址 | 返回 `{"ok":true,"service":"lottery-proxy"...}` |
| 便捷入口 | 访问 `https://你的地址/?lot=ssq&n=3` | 返回双色球 JSON |
| **CI 实际分支** | 访问 `?url=<编码后的福彩接口地址>`（完整拼法见 2.9） | 返回福彩 JSON 原文，与定时抓取走同一段代码 |
| 诊断端点 | 访问 `?diag=1` | 回显 event 关键字段 |
| 工作流自检 | Actions → 定时刷新彩票数据 → 看「检查云代理配置与连通性」 | 打印 `云函数自检 HTTP 200` 与响应片段 |
| 端到端 | 手动 **Run workflow** 跑一次定时刷新 | 日志里四彩种都抓到、推送了 `dist/` 的提交 |
| 发布结果 | 部署工作流跑完后强刷页面 | 顶部「数据更新于」变成刚才的时间 |
| 页面手动更新（体彩） | 菜单「数据更新」→「只更新体彩」 | 显示「已是最新」或新增期数，无失败提示 |
| 页面手动更新（福彩） | 配好代理后点「全部更新」 | 双色球 / 福彩3D 也显示「已是最新」或新增期数 |

## 六、排错

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 控制台找不到「API 网关触发器」 | 已下线 | 按 2.7 用**函数 URL** |
| 访问地址提示需要签名 / 403 | 授权类型选了 CAM 鉴权 | 函数 URL 配置改成**开放** |
| 浏览器 `ERR_INVALID_RESPONSE` / 打不开地址 | 先定位是代码还是入口，不要反复改 CORS 配置（CORS 只作用于请求到达函数之后的跨域） | 按下方「地址打不开时如何定位」二分排查 |
| 打开根路径看不到自检 JSON | 请求没到达函数，或部署的是旧版代码 | 确认已粘贴本源码并部署过；再用 `?diag=1` 与最小函数定位 |
| 浏览器报 `No 'Access-Control-Allow-Origin' header` | 启用了控制台 CORS 且 Allow-Origin 留空 | 填 `*`，保存后重开页面；或直接关掉控制台 CORS 只留代码返回的头 |
| 预检 `OPTIONS` 失败 / 405 / 方法不允许 | 启用了控制台 CORS 且 Allow-Methods 一个都没勾 | 勾 `GET`（或最左 `*`） |
| 点「确定」报 `InvalidParameterValue.Cors` / `(Invalid ExposeHeaders: )` | 启用了控制台 CORS 且 Expose-Headers 留空 | 填 `*`；或取消勾选 CORS，只靠代码返回的头 |
| 浏览器控制台 CORS 报错 | 代码返回头与控制台 CORS 配置重复，或没生效 | 先看响应头；重复就关掉控制台那处 CORS |
| 换了函数版本后地址失效 | 函数 URL 与别名/版本一对一绑定 | 到「函数 URL」为新版本再建一个，并同步更新应用里的地址 |
| 返回一整坨 HTML 而不是 JSON | 代码没部署成功 / 函数 URL 绑错版本别名 | 重新部署 `index.py` |
| 返回 `缺少参数：url 或 lot` | 部署的是早期源码；配套源码的根路径返回 200 自检 JSON | 重新粘贴配套源码并部署；地址末尾也不要多写 `?url=` |
| 抓取日志里出现 `?url=` 相关失败 | Secret 末尾多写了 `?url=`，变成两个 url 参数 | 改掉 Secret，重新 Run 一次 |
| `域名不在白名单内` | 拼出的目标地址不在放行列表 | 检查代理地址是否被截断 |
| `上游请求失败` | 云函数出口 IP 被彩票站限流 | 等几分钟重试，**不要频繁点**，越点限流越久 |
| 工作流报「未配置仓库 Secret LOTTERY_PROXY」 | Secret 没建或名字写错 | 按第四节重新建一个，名字必须完全一致 |
| 四彩种全部抓取失败 | Secret 地址失效或云函数不可达 | 按第五节的根路径自检与「检查云代理配置与连通性」逐级确认 |
| 数据一直不更新但工作流全绿 | 抓取回落到了过期缓存，或部署工作流没被触发 | 看定时工作流日志里是否有 `CHANGED=yes`，并确认 `deploy-pages.yml` 跑过 |
| 超时无响应 | 执行超时还是默认 3 秒 | 函数配置改成 30 秒 |
| `内部错误` | 运行时报错 | 去控制台看函数日志 |

### 地址打不开时如何定位（不用配日志、不花钱）

控制台「日志查询」页需要先启用**日志投递**并完成配置才能看到调用日志；未配置时页面为空，这是正常现象。更快的办法是用控制台自带的运行按钮做二分定位：

**第 1 步**：把 `src/index.py` 的内容**临时**全部替换成下面 5 行，点「部署」：

```python
def main_handler(event, context=None):
    return {
        "statusCode": 200,
        "headers": {"Content-Type": "text/plain; charset=utf-8"},
        "body": "hello from scf",
    }
```

**第 2 步**：点函数代码页工具栏的 **▶「运行」**，右侧应输出 `hello from scf`。若这里就报错，先解决执行方法 / 模块路径问题。

**第 3 步**：在浏览器打开**完整 https 地址并带参数**（不要只输裸域名，浏览器可能默认走 `http://`）：

```
https://125xxxxxxx-abcdefgh.ap-guangzhou.tencentscf.com/?x=1
```

- **能看到 `hello from scf`** → 函数 URL、权限、执行方法都是好的，问题在代理源码或部署版本，把 `cloud_proxy.py` 重新粘回去部署即可
- **仍打不开** → 与代理代码无关，是函数 URL / 网络 / 客户端层面的问题。按 **F12 → Network** 看那条请求的 Status 与 Response 原文，再换手机流量或另一台设备试一次；状态码比错误文案准

**第 4 步**：恢复源码部署后访问 `?diag=1` 与根路径，确认参数位置与自检 JSON 都正常。

### 云代理暂时不可用时的兜底

- 本地工程包里 `一键更新并推送.bat`、`刷新数据.bat`：在自己电脑上跑 `crawler.py`（不设 `LOTTERY_PROXY` 环境变量即直连），用家庭宽带境内 IP 抓完生成产物再推送仓库
- 也可以给云函数加**定时触发器**，让它定时把抓到的结果写回仓库，绕开函数 URL 这条入口
- 页面本身不依赖云函数：即使云端抓取停了，已发布的页面仍可正常查看历史数据

## 八、安全

`cloud_proxy.py` 写死了域名白名单：

```python
ALLOW_HOST = (
    "www.cwl.gov.cn", "cwl.gov.cn",
    "webapi.sporttery.cn", "www.sporttery.cn",
)
```

除了彩票官方域名，其它一律返回 403。这是故意的——开放代理会被拿去滥用，最后出口 IP 被封、账号被停。

要清楚一点：函数 URL 的「授权类型 = 开放」意味着**任何人可以匿名调用**；CORS 只约束浏览器，拦不住 `curl`。所以真正的防线是这份白名单，不是 CORS 也不是 URL 保密。地址被别人拿到，也只会被用来查彩票开奖数据。

## 附 B：本地自测

不想先部署，可以在电脑上先跑一遍（需要 Python 3）：

```bash
cd lottery-app
python3 cloud_proxy.py
```

脚本会依次打印根路径自检、诊断端点、函数 URL 原生 event、参数兼容 event 的响应，最后用本机网络请求一次双色球接口。能打印出双色球 JSON 开头，说明代码本身没问题，再拿去部署。

也可以单独验根路径自检：

```bash
python3 -c "import cloud_proxy; print(cloud_proxy.main_handler({})['body'])"
```

本地自测走的是自己网络的出口 IP；若被限流，稍等再试，不代表云函数上会失败。部署后打开函数 URL 看不到自检 JSON，按第六节的方法定位，不要凭猜测改配置。
