# 彩票统计 · 项目实现与部署文档

本文说明这个项目**是怎样实现的**、**如何从代码走到线上部署**，以及**维护时必须知道的重要点**。内容以仓库中的实际代码为准：前端源码 `static/index.html`、抓取与构建脚本、两个 GitHub Actions 工作流、云函数源码，以及两份交付包。

> 本文是一份实现文档，不是操作清单的替代品。云函数逐屏配置请看 `云代理部署说明.md`，仓库设置与排错请看 `Pages部署说明.md`（它在 `GitHub上传包.zip` 里也叫 `README.md`）。

### 0.3 设计目标

1. **纯静态、无后端**：页面是 HTML，不需要服务器接口、数据库或登录态服务。
2. **数据构建期内嵌**：访客打开页面不向彩票站发任何请求，离线也能看全部历史与统计。
3. **自动更新**：开奖数据由云端工作流定时抓取、重建、发布，页面里没有手动更新按钮。
4. **可分享**：单文件版双击可看，也可以直接发给别人；网址版用于 GitHub Pages。

## 3. 数据层：官方接口到 `data/*.json`

### 3.1 四个官方接口

地址全部写在 `crawler.py` 里，不在页面上。

| 彩种 | 接口 | 关键参数 | 解析要点 |
|---|---|---|---|
| 双色球 `ssq` | `https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice` | `name=ssq&issueCount=N` | `red` 逗号分隔 6 个红球，`blue` 1 个蓝球；红球排序后存 |
| 福彩3D `3d` | 同上 | `name=3d&issueCount=N` | `red` 是 3 位数字，**可重复、分顺序**；用 `positional:true` 标记 |
| 大乐透 `dlt` | `https://webapi.sporttery.cn/gateway/lottery/getHistoryPageListV1.qry` | `gameNo=85&provinceId=0&pageSize=100&isVerify=1&pageNo=N` | `lotteryDrawResult` 7 个数：前 5 为前区、后 2 为后区 |
| 排列三 `pls` | 同上 | `gameNo=35&provinceId=0&pageSize=100&isVerify=1&pageNo=N` | 3 位数字，按位玩法 |

> 体彩接口必须带 `provinceId=0&isVerify=1`，缺参数会返回参数不合法。

统一的行结构（按期号升序）：

```
[期号, 开奖日期(YYYY-MM-DD), 主号数组, 副号数组]
```

每份 JSON 还带元数据：`name` / `redMax` / `blueMax` / `redCount` / `blueCount` / `redLabel` / `blueLabel` / `positional` / `posLabels` / `minNum` / `pool`（最新奖池与销售额）/ `poolHist`（最近 120 期奖池序列）/ `count` / `source` / `updatedAt` / `buildDate`。`build_single.py` 的 `META_KEYS` 白名单决定哪些字段会进产物。

### 3.2 抓取器 `crawler.py`

| 机制 | 实现 |
|---|---|
| 请求头 | 4 个 UA 轮换；福彩带 Referer，体彩带 Referer + Origin |
| 重试 | `_retry()` 6~8 次，退避 `1.2 + 0.9*i + 随机`；出现 403 / 567 / Forbidden 只再给一次机会，然后抛 `IPBlocked`，避免高频重试加重封禁 |
| 缓存 | 内存 + 磁盘双级，`CACHE_DIR` 默认系统临时目录，TTL 默认 21600 秒（6 小时） |
| 全量抓取 | 福彩一次取全部（`issueCount=3000/8000`）；体彩按 `total` 算页数并发抓取，缺页串行重试，末尾探测到空页为止 |
| 增量抓取 | 缓存里已有 >500 期时，只取福彩最近 60 期（`LOTTERY_INC_COUNT`）、体彩最近 1 页（`LOTTERY_INC_PAGES`），请求量降到个位数 |
| 合并 | `_merge()` 按期号去重合并；新数据没有 `pool` 时保留旧的；`poolHist` 合并去重后截到最近 120 期，**避免增量把走势图序列截断** |
| 失败回落 | `get_data_safe()` 在实时抓取失败时回落到过期缓存并返回 `source="stale"` |
| 代理转发 | 环境变量 `LOTTERY_PROXY` 非空时，`_http()` 把请求改写成 `<代理>?url=<URL 编码后的官方地址>` |

### 3.3 定时刷新脚本 `cron_refresh.py`

它是工作流直接调用的程序，负责把"抓一次"变成"可靠地更新一次"：

1. `seed_cache()` 把仓库里 `dist/static_site/data/*.json` 预填到抓取器的磁盘缓存，并写 `_t = 0` 让 TTL 失效、必须真去抓一次，但合并时仍以它为全量基准。
2. `DRAW_DAYS` / `DRAW_HOUR` / `DRAW_MIN` 定义各彩种开奖日与开奖时刻；只有「开奖日且已过开奖时刻」**且本地最新一期的开奖日期还没覆盖今天**才轮询。`already_has_today_draw()` 读仓库数据最后一期的日期，若当期已入库就跳过等待；轮询循环里还有一道兜底：官方最新一期的开奖日期已覆盖今天、且与本地期号相同，也立即停止等待。`probe_latest()` 每隔 90 秒探一次最新期号，直到期号变化或超过 `--poll-minutes`（默认 12 分钟）。
3. `fetch_one()` 的三条保护：
   - `src == "stale"` 直接判失败——否则 CI 会把旧缓存当新数据写回，出现「全绿但数据从不更新」；
   - 抓到的最新期号比仓库已有还旧，放弃本次更新；
   - 返回空数据跳过。
4. 成功的彩种写入 `dist/static_site/data/*.json`，随后调用 `build_single.build()` 重建单文件版。
5. 对比前后 md5，输出 `CHANGED=yes|no`、`FAILED=...`；任一彩种失败就退出码 1（让 job 变红），但已成功的部分照常写入。唯一例外是「全部失败都源于 IP 风控」，这时降级为警告并退出 0，避免天天飘红淹没真实故障。

> 注意：`cron_refresh.py` 只调用 `build_single.build()`，**不会重建 `dist/static_site/index.html`**。网址版首页的 HTML 若要同步新版源码，需手动跑 `build_static.py`。Pages 用的是单文件版，所以不影响线上主链路。

## 4. 网络层：境内云函数 `cloud_proxy.py`

### 4.1 为什么需要它

GitHub Actions 的 runner 出口 IP 在境外共享段，彩票站按 IP 段风控，直连常见 403 / 567。云函数部署在境内，出口 IP 不在被封段内；`crawler.py` 把所有官方请求交给它转发。

福彩 `www.cwl.gov.cn` 不返回 CORS 头、也不支持 JSONP；体彩 `webapi.sporttery.cn` 自带 `access-control-allow-origin: *`。当前架构里浏览器**完全不取数**，所以 CORS 只影响可选的浏览器直连场景，云函数仍统一带 CORS 头。

### 4.2 对外接口

| 请求 | 行为 |
|---|---|
| `?url=<URL 编码后的官方地址>` | 校验域名白名单后代为请求，原文返回。**CI 抓取走这一条** |
| `?lot=ssq\|3d\|dlt\|pls&n=N` | 便捷入口，直接返回该彩种最近 N 期；工作流连通性自检用 `?lot=ssq&n=1` |
| `?diag=1` | 回显 event 里的 `httpMethod`、`queryString`、是否有 `queryStringParameters` 等，用于定位参数落在哪一层 |
| 根路径（不带参数） | 返回 200 自检 JSON `{"ok":true,"service":"lottery-proxy",...}`，用于确认函数已部署、请求确实到达函数 |
| `OPTIONS` | 直接返回 200，处理预检 |

### 4.3 代码要点

- `ALLOW_HOST` 只放行 `www.cwl.gov.cn`、`cwl.gov.cn`、`webapi.sporttery.cn`、`www.sporttery.cn`，防止被当作开放代理滥用。
- `_q()` 依次兼容 `queryString` / `queryStringParameters` / `queryParameters` / `query` / `params` / `body`（含 JSON 字符串 body），并跳过重复参数里的空值。
- `_ok()` 返回 `{isBase64Encoded:false, statusCode, headers, body}`，`headers` 带 `Access-Control-Allow-Origin: *`、`GET, OPTIONS`、`Allow-Headers: *`。
- 三个入口名 `main_handler` / `handler` / `lambda_handler`，对应腾讯云 SCF、阿里云 FC / 华为云 FunctionGraph 的常见入口。
- 只用 Python 标准库，不需要打包依赖。

### 4.4 接入仓库的方式

云函数地址配置为仓库 Secret **`LOTTERY_PROXY`**（Settings → Secrets and variables → Actions → Repository secrets）。地址末尾**不要带 `?url=`、不要引号、不要换行**，`crawler.py` 会自己根据地址里是否已有 `?` 决定拼 `?url=` 还是 `&url=`。

同一个值被两处读取：

- `crawler.py`：作为环境变量转发官方请求；
- `build_single.py` / `build_static.py`：作为构建期常量替换源码里的 `@@PX_BUILTIN@@`。

页面里 `PX_BUILTIN` 仅用于「数据来源」弹窗显示通道状态（已配置 / 未在本文件内置），**不参与取数**；不配置也能正常构建与阅读。

## 5. 构建层：从源码到两种产物

### 5.1 `build_static.py` → 网址版

1. 读 `static/index.html`，把 `var STATIC_BUILD = false;` 改成 `true;`（关闭后端回退）。
2. 若存在 `license.json`，把其中的 `salt` / `expire` / `codes` / `sigSalt` / `admin` / `regUrl` 内嵌为 `LICENSE`（**只含散列，不含明文授权码**）。
3. 替换 `@@PX_BUILTIN@@`。
4. 调 `pwa_assets.install_pwa()` 写出 `manifest.json`、`sw.js`、三个图标。
5. `ensure_meta()` 给旧数据补 `updatedAt` / `buildDate`，避免页面显示 `Invalid Date`。
6. 输出 `dist/static_site/index.html`，数据仍是运行期 `fetch('./data/xx.json')`。

### 5.2 `build_single.py` → 单文件版（Pages 用这个）

1. 读四份 `data/*.json`，补 `updatedAt` / `buildDate` / `embedded` / `staticMode`，序列化成**一段 JSON 字符串**。
2. 在页面第一个 `<script>` 前注入一段脚本：
   - `EMBEDDED_META`：各彩种期数、最新期号、时间戳，组成 `st` 命中标记；
   - `EMBEDDED_SRC`：全部数据的字符串字面量（相比对象字面量，JS 引擎只需扫描文本，首次解析更快）；
   - `embeddedLoad(lot)`：先查 `localStorage` 的 `lcst_<lot>` 与 `lcd_<lot>`，命中就不解析大字符串；否则 `JSON.parse` 一次并写回缓存；
   - **fetch 垫片**：拦截 URL 里含 `ssq|dlt|3d|pls` 的请求，直接返回内嵌数据。`file://` 下原生 fetch 可能永久挂起，这一步保证双击打开也能渲染。
3. 把 `load()` 里的静态读取分支改写为「优先 `embeddedLoad()`，并把结果写入 `D[lot]`」，再保留原来的 `fetch('./data/...')` 作为回退。
4. 注入 `STATIC_BUILD = true` 与 `EMBEDDED_BUILD = true`。
5. `pwa_assets.inline_pwa()` 把 manifest 与 apple-touch-icon 转成 data URI 内嵌；**Service Worker 无法注册 data URI**，单文件版只做「添加到主屏幕有图标」，离线能力靠数据本身已烤进文件。
6. 内嵌 `LICENSE`（逻辑同网址版）。
7. 末尾注入 3 秒兜底：若页面仍停在「正在加载」，直接用内嵌数据强制 `render()`。
8. 输出 `dist/单文件版/彩票统计.html`，约 1.10 MB。

### 5.3 两种产物对比

| | 网址版 `index.html` | 单文件版 `彩票统计.html` |
|---|---|---|
| 数据 | 运行期 `fetch('./data/*.json')` | 编译期烤进 HTML，零网络请求 |
| 离线 | 首次需联网，之后靠 `sw.js` 缓存 | 双击即可，完全离线 |
| 体积 | 约 382 KB + 四份 JSON | 约 1.10 MB（含数据） |
| PWA | 完整 manifest + Service Worker | 仅内嵌图标与 manifest data URI |
| 用途 | 任意静态托管、需要外链数据时 | **GitHub Pages 当前发布的就是它**；也可直接发给别人 |

### 5.4 构建期常量与运行时配置的分界

当前版本**没有** `proxy.json`、没有「在线更新」面板、没有代理输入框。所有配置都在构建期决定：云函数地址走 Secret → 环境变量 → 产物常量；授权走 `license.json` → 内嵌 `LICENSE`。页面运行时只读取内嵌数据与用户本机数据，不读取站点配置文件。

## 6. 前端实现 `static/index.html`

### 6.1 总体结构

单个 HTML 文件，内联 CSS、内联 JS、`HELP_SECTIONS` 说明数组，共 7277 行、约 460 处函数声明。几个全局对象：

| 对象 | 作用 |
|---|---|
| `D` | 四彩种已加载的数据 |
| `S` | 全部 UI 状态：当前彩种 `lot`、页签 `tab`、排序、选号球、核对模式、猜号参数等 |
| `STATIC_BUILD` / `EMBEDDED_BUILD` | 构建时注入的模式标记 |
| `LICENSE` | 构建时内嵌的授权配置，默认 `null`（不启用） |
| `PX_BUILTIN` | 构建期云函数地址占位符，只用于状态显示 |
| `TABS` | 页签注册表 |

`render()` 是唯一总入口：先检查授权锁屏，再确认数据已加载，然后 `renderTabs()` → `head() + latest()` → 按 `TABS` 表调用对应渲染函数。`tabCall()` 给每个页签包了 try-catch，某个页签出错只在那块显示错误，不会整页白屏。`visibleTabs()` 根据 `isPos()`（是否按位玩法）过滤带 `hidePos:true` 的页签。

### 6.5 猜号参考（`renderGuess`）

这是页面里算法最密集的一块，按代码顺序：

1. `guessProfile()` 取最近若干期统计**历史形态基线**：和值区间、跨度、奇数个数、连号上限、与上期重号上限、按位玩法的豹子/组三/组六分布。
2. 六种偏好 `STRS`：`morph`（形态典型，默认）、`hot`、`cold`、`gap`（遗漏回补）、`balance`、`random`；非 `morph/random` 时可设偏向强度，`guessWeights()` 用 z-score 标准化后指数放大，保留号码热度的真实离散度。
3. `guessMorphOK()` 检查组合是否落在形态基线内；`guessTooSimilar()` 控制多注之间红球重合；`guessRecentOK()` / `guessRecentViolation()` 实现**近 N 期避重**：
   - 默认 A（逐期）：与近 N 期每一期分别比，任意一期重合 ≤ M；
   - 严格 B（并集）：与近 N 期出现过的全部号码合计重合 ≤ M；
   - N 可选 3/5/10，M 可选 1/2/3；按位玩法因为只有 10 个数字，严格模式改用「同位命中 ≤ 1 且不复制近 N 期任一期」。
4. 约束是**软约束**：先按全条件抽，再逐步放宽，最后取违反程度最小的一注并标注，保证一定出号，不会卡死；也不会因为硬拒绝把「多注反雷同」拖垮。
5. 每注可展开详细分析：`guessNumTable()` 给出每个球的历史次数 / 占比 / 当前遗漏 / 冷热标签，`guessNearest()` 找全史最相近一期与命中分布，`guessSumPct()` 给和值百分位，还有近 N 期重号矩阵。
6. `guessBacktest()` 对最近若干期逐期回放（只使用该期之前的数据），对比各偏好与「近 N 期避重」列的平均命中数，并与 `guessTheory()` 的理论值并列。
7. **蓝球 / 后区指定**：`guessBlueSpec()` 解析「自动 / 指定号码 / 排除号码」与输入框（校验范围、去 0、去重）；`guessPlanBlues(spec, i, need, blueMax)` 在 `guessRun()` 里**先为第 i 注定好蓝球**：指定模式按 `(i*need+j) % list.length` 轮流取，大乐透后区需要 2 个、指定不足时从合法号补齐；排除模式从剩余号码随机取。只对生成批次生效，回放 `guessBacktest()` 仍走自动的按权重采样；按位玩法 `isPos()` 自动隐藏控件。被指定的球加 `.pin` 高亮。
8. **红球与蓝球重合**：`S.guessRB` 三档 `any`（不限，默认）/ `avoid`（蓝球不与本注红球同数字）/ `must`（至少一个蓝球号与红球相同）。这是**采样阶段的硬约束**：蓝球先定好，`guessOneRaw(..., rbCfg)` 采红球时，`must` 把某个蓝球数字作为种子强制入选，`avoid` 通过 `guessSample(..., ban)` 从候选里剔除蓝球数字；`guessOne()` 里的 `rbOK()` 再做一道校验，三级放宽中绝不放宽这一条。双色球蓝球 1~16、大乐透后区 1~12 都落在红球范围内，所以「指定号码 + 必须重合」永远有解，不需冲突标注——例如指定 13 且必须重合时，每注红球都含 13。结果区给出「x/x 注达标」，重合的红球加 `.rbhit` 蓝边；`guessDetail()` 显示具体重合号码与达标状态。折叠的「按条件机选」由 `genPlanBlues()` + `genRedCand()` 共用同一口径。
9. **生成功能合并**：「我的选号」不再放条件机选面板，改用 `guessGo()` 引导到猜号参考；`renderGen()`（和值 / 奇偶 / 大小 / 三区）以折叠入口挂在猜号页，默认收起。每注点「存入」调 `guessSave()`，只写入 `myBets_<lot>`（`t` 用 `Date.now()` 毫秒数字）；在「我的选号」点「标记为已买」时才由 `archiveBought()` 写入 `lc_rec`。按钮变「已存入 ✓」并在结果区给出本批计数与「去查看」入口。

**时间戳的一个坑**：`recRow()` / `betResult()` 用 `t` 与开奖日期比大小来定位「买的是哪一期」。若 `t` 被写成 `'YYYY-MM-DD HH:mm'` 字符串，比较得到 `NaN`，自动对奖会错用全史最早一期。`getBets()` / `getRecs()` 读时经 `normTs()` 归一化并回写，`betsOfAll()`、`fmtTs()` 也走同一函数，兼容历史遗留数据。

**必须写清楚的边界**：这些约束（含指定蓝球）不改变任何中奖概率。页面里已用红框说明——它解决的是「号码看着怪」和「多注雷同浪费钱」两个体验问题，回放表的作用是证明各策略与随机机选没有稳定差距。

### 6.6 授权与管理员

`LICENSE` 存在时，页面先显示锁屏，凭授权码激活；`licH()` 是三轮 FNV 变体散列，`licFp()` 采集浏览器指纹，`licDevId()` 结合本机随机串派生设备 ID。可选 `regUrl` 指向公共 JSON 登记表，实现一码一机。

锁屏由 `render()` / `boot()` 在 `licBlocked()` 时直接输出 `renderLock()`，不渲染数据页。为避免管理员本人也被挡在门外，`renderLockChrome()` 给标签栏补一个「菜单」按钮，侧边抽屉里的「访问授权」「管理员」照常可打开；锁屏卡片只显示本机 4 位设备码与「发给管理员生成授权码」的提示，不放登录按钮。管理员从菜单登录后 `licValid()` 直接返回 true（免激活），`admLogin()` 会重跑 `boot()` 进入完整页面并弹出「生成授权码」，在「设备绑定」填入设备码即可签发；首次启用可以在同一台设备上完成「登录 → 签发绑定码 → 激活」。

管理员登录态存 `sessionStorage`；`admNow()` 优先读本机改密记录（`base` 必须等于当前内嵌散列，否则丢弃），否则用构建时的 `LICENSE.admin.hash`。「修改密码」的成功页提供下载 `license.json`、复制完整配置、下载账号备忘三个出口——**本机立即生效，但要让所有访客生效必须重建并推送**。

**安全边界**：这是纯前端校验。散列算法、salt、授权码签发逻辑都在 HTML 里，能挡住「拿到链接但没有码」的人，挡不住刻意扒源码的人；要做到不可伪造必须上后端签名。

### 6.7 PWA 与缓存

`sw.js` 只在 https / localhost 注册，缓存名 `lottery-v1`，采用**网络优先、失败回落缓存**策略，预缓存 `index.html`、`manifest.json` 和四份数据。这正是「部署成功但页面还是旧的」的常见原因：覆盖发布后按 `Ctrl+F5`，或清一次站点数据 / 用无痕窗口。

### 6.8 说明与 UI 基础

- `HELP_SECTIONS` 是章节数组（当前 16 章），`showHelp()` 循环渲染；改说明只需改数组里的一条。内容只讲「怎么用」，不含抓取、构建、云函数等实现说明；「数据来源」弹窗同样只列官方来源与当前期数。
- `modalBox()` / `modalPanel()` 统一弹窗，`esc()` / `escA()` 做 HTML 与属性转义。
- 主题默认跟随时间自动切换（19:00–07:00 深色），可手动锁定。
- 备份 / 恢复用文本或二维码同步（`qrEncode()` 是内嵌的二维码编码器），外部数据入口会经过转义与长度限制。

## 7. 自动化更新与部署

### 7.1 `refresh-data.yml`（定时刷新彩票数据）

| 项 | 内容 |
|---|---|
| 触发 | `schedule` 两条：`43 13 * * *`、`13 1 * * *`（UTC，对应北京 21:43 / 次日 09:13）；`workflow_dispatch`（可指定轮询分钟数，默认 12）；push 到 main（排除 `dist/**` 与 `*.md`，避免自我循环） |
| 权限 | `contents: write`（推送 `dist/`）、`actions: write`（`gh workflow run`） |
| 环境 | job 级 `LOTTERY_PROXY: ${{ secrets.LOTTERY_PROXY }}` |
| 步骤 1 | checkout、Python 3.11、装 `requirements.txt` 与 `requests` |
| 步骤 2 | **检查云代理配置与连通性**：Secret 为空直接 `exit 1`；否则请求 `?lot=ssq&n=1` 并打印 HTTP 状态与响应片段 |
| 步骤 3 | `python3 cron_refresh.py --poll-minutes 12 2>&1 \| tee cron.log`，从日志提取 `rc`、`changed`、`failed` |
| 步骤 4 | `CHANGED=yes` 时提交并推送 `dist/` |
| 步骤 5 | `gh workflow run deploy-pages.yml --ref main` 显式触发部署 |
| 步骤 6 | `CHANGED=no` 时写 `dist/.last-check` 心跳提交，防止公开仓库 60 天无 activity 被禁用定时任务 |
| 步骤 7 | `rc != 0` 时最后一步 `exit 1`，让 job 变红并打印排查方向 |

### 7.2 `deploy-pages.yml`（部署到 GitHub Pages）

触发条件：`workflow_dispatch` 手动，或 push 到 main 且命中 `dist/单文件版/**`。步骤只有三步：

1. `mkdir -p _site` 并把 `dist/单文件版/彩票统计.html` 复制成 `_site/index.html`；
2. `grep -c "EMBEDDED_DATA"` 校验数据确实内嵌，避免发布空壳；
3. `actions/upload-pages-artifact@v3` 上传 `_site`，`actions/deploy-pages@v4` 发布。

因此 **Pages 实际发布的是单文件版**，仓库根目录的 `index.html`、`data/`、网址版首页都不参与这次发布。

### 7.3 一个必须理解的机制

`refresh-data.yml` 用 `actions/checkout` 默认的 `GITHUB_TOKEN` 推送提交。**由该令牌产生的 push 不会创建新的 workflow 运行**，所以 `git push dist/` 不会自动触发 `deploy-pages.yml`；只依赖 `on: push` 的路径过滤会出现「仓库产物已是新的、Pages 仍是旧的」。

解决办法就是工作流末尾的 `gh workflow run deploy-pages.yml`：`workflow_dispatch` 属于例外，显式调用能触发部署。

> 区分清楚：**人用自己的账号 push** 会正常触发 `on: push`；**工作流内用 GITHUB_TOKEN push** 不会。两者别混为一谈。

### 7.4 完整链路

```
refresh-data.yml（定时 / 手动）
  └─ 云函数连通性自检
  └─ cron_refresh.py
       ├─ seed_cache（仓库全量数据预填）
       ├─ crawler.py ──?url=──> cloud_proxy.py ──> 官方接口
       ├─ dist/static_site/data/*.json（增量合并）
       ├─ build_single.py → dist/单文件版/彩票统计.html
       └─ CHANGED=yes / FAILED=...
  ├─ git add dist/ && git push
  ├─ gh workflow run deploy-pages.yml
  │    └─ _site/index.html → Pages Artifact → GitHub Pages
  └─ 无变化时写心跳提交
```

## 9. 重要的点

以下是最容易出问题、或最容易被误解的地方，按重要程度排列。

### 9.1 数据更新链路

1. **境外 IP 风控是架构的根因。** GitHub Actions / Render / Vercel / onrender 的出口在境外共享段，彩票站按段返回 403 / 567。云函数必须部署在境内；所有官方请求都经 `?url=` 转发，去别处部署等于回到原问题。
2. **`GITHUB_TOKEN` 推送不触发新工作流。** 这是「`CHANGED=yes`、仓库产物已更新，但页面数据仍是旧的」的唯一原因。定时工作流末尾必须显式 `gh workflow run deploy-pages.yml`；临时补救是手动 Run 一次部署工作流。
3. **Pages 发布的是单文件版。** `deploy-pages.yml` 只复制 `dist/单文件版/彩票统计.html`。改根目录 `index.html` / `data/` 不会影响 Pages 页面；两套产物别混着改。
4. **Service Worker 会缓存旧页面。** 覆盖发布后看不到变化，`Ctrl+F5` / 清站点数据 / 无痕窗口；`sw.js` 本身是网络优先，但浏览器仍可能持有旧 HTML。
5. **构建产物必须提交进仓库。** `dist/static_site/data/*.json` 既是增量合并基准，也是构建输入；`dist/单文件版/` 是发布来源。缺了它们，定时任务会退化成全量重抓或直接失败。
6. **`stale` 缓存不能当成功。** `get_data_safe()` 失败会回落过期缓存；`cron_refresh.py` 明确把 `src == "stale"` 判为失败，否则会写出与仓库一模一样的内容，`CHANGED=no`、job 全绿、数据永远不更新。
7. **增量合并要保住 `poolHist`。** 增量只带回最近几期，直接覆盖会把 120 期奖池序列截短，走势图变空。`_merge()` 采用按期号合并去重再截断。
8. **CI 只重建单文件版。** `cron_refresh.py` 调 `build_single.build()`，不调 `build_static.py`。网址版 `dist/static_site/index.html` 不会随数据自动重建，需要同步时手动跑一次。
9. **`.nojekyll` 要保留。** 少了它，GitHub Pages 的 Jekyll 处理可能让下划线目录或静态文件不按预期发布。
10. **CI 重建会重新决定授权是否开启。** 授权配置不是运行时读取，而是 `build_single.py` 构建时把 `static/index.html` 里的 `var LICENSE = null;` 替换成内嵌配置。仓库根目录缺 `license.json`，自动重建的发布产物就是无授权版；本地手工构建好的成品也会被下一次定时任务覆盖。所以授权要长期生效，只能靠仓库里那份 `license.json`。
11. **心跳提交是必要的。** 公开仓库 60 天无 activity 会被静默禁用定时任务；`CHANGED=no` 时写 `dist/.last-check` 保活，且该路径被 `paths-ignore` 排除，不会循环触发。

### 9.2 配置与安全

12. **Secret 格式最容易填错。** 只填函数 URL，不带 `?url=`、不带引号换行。填错会出现两个 `url` 参数或转发失败；`cloud_proxy.py` 的 `_q()` 会跳过空值，但最好从源头避免。
13. **云函数「授权开放」意味着任何人可匿名调用。** 真正的防线是 `cloud_proxy.py` 里的四个域名白名单，不是 URL 保密；别把它改成任意地址转发。
14. **区分明文文件与散列配置。** `管理员账号.txt`、`授权码名单.txt`、改密备忘含明文，只留本地；`license.json` 只含散列，**必须提交到仓库根目录**。`cron_refresh.py` 每次重建产物都重新读它，仓库缺文件时新产物 `LICENSE = null`，管理员与访问授权入口一起消失（页面菜单少两项是症状，不是源码被删）。`refresh-data.yml` 已加「校验授权配置未被构建丢弃」一步，遇到这种静默丢失会报红并停止发布。
15. **授权是纯前端校验。** 能挡随手试密码，挡不住扒源码。管理员改密码分两层：本机 localStorage 立即生效，所有访客生效必须导出配置 → 重建 → 推送；重建后本机旧记录因 `base` 对不上自动作废。
16. **`PX_BUILTIN` 不是运行时配置。** 它只是构建期写进产物的常量，供「数据来源」显示通道状态；页面没有 `proxy.json`、没有在线更新入口，也不需要访客配置任何地址。

### 9.3 页面与代码

17. **猜号参考不是预测。** 六种偏好、形态约束、近 N 期避重都不改变中奖概率；页面用回放对比和理论值自证这一点。它解决的是「号码看着怪」与「多注雷同」。
18. **按位玩法是另一套分支。** 福彩3D / 排列三可重复、分顺序，`isPos()` 会把走势、统计、核对、复式、猜号切到对应函数，并隐藏蓝球分析 / 奖池走势两个必然空白的页签。
19. **功能说明面向使用者。** 已精简为 16 章，去掉「数据更新」等实现性章节与页签合并沿革；抓取链路、构建与部署只写在 `Pages部署说明.md`、`云代理部署说明.md` 和本文档里，页面不重复。
20. **`S.tab` 初始值为 `'hist'`。** `render()` 仍保留 `tabDef()` 回退，兼容本机存下的老页签 id，避免空白。
21. **`requirements.txt` 不能删。** 定时工作流里有 `pip install -r requirements.txt`；内容是早期后端依赖，抓取链路只用标准库与工作流另装的 `requests`，别把它当成抓取链路的依赖说明。
22. **顶层 `README.md` 不是本项目文档。** 工作区根目录那份是早期 v8.0 分析系统说明；仓库 / 上传包里的 `README.md` 才是 `Pages部署说明.md`。
23. **选号记录只保存已购买的注。** 「添加」「粘贴」「复式生成」「猜号存入」一律只写 `myBets_<lot>`；只有 `toggleBetBought()` / `slipBuyAll()` 标记已买时才调 `archiveBought()` 写入 `lc_rec`。`getRecs()` 读时会清掉早期版本自动写入的未购买条目。记录页因此没有「购买」筛选，也没有「标记为已买」按钮；未购买的号在「我的选号」工作列表里查看。

## 10. 故障速查

| 现象 | 优先检查 |
|---|---|
| 页面 404 | Pages Source 是否为 **GitHub Actions**；仓库根目录本来就没有作为 Pages 首页的分支部署文件 |
| 抓取 403 / 567 | Secret 是否指向境内云函数；云函数根路径自检是否 200；上游是否临时限流 |
| 日志显示「直连（未配置 LOTTERY_PROXY）」 | Secret 名字、位置（Repository secrets）、是否在 job 级 `env` 注入、运行分支是否正确 |
| `CHANGED=yes` 但页面没变 | 部署工作流是否被触发；`gh workflow run` 那步是否执行；`Ctrl+F5` 绕过缓存 |
| 全部彩种失败、job 却绿 | 看 `FAILED=` / `BLOCKED=yes`，这是 IP 风控的降级分支，不是成功 |
| 页面显示 `数据更新于 Invalid Date` | 旧数据缺 `updatedAt` / `buildDate`；`build_static.py` 的 `ensure_meta()` 会补 |
| 推送失败 `permission denied` | Workflow permissions 是否为 Read and write |
| 定时任务长期不跑 | 公开仓库 60 天禁用；手动 Run 一次恢复，心跳提交是否还在写 |
| 双色球 / 福彩3D 抓不到，体彩正常 | 检查云函数 `?url=` 转发分支（体彩便捷入口与转发是两条代码路径） |
| 本机改了管理员密码，别人还是旧密码 | 只改了 localStorage；需导出 `license.json` 重建并推送 |
| 菜单里没有「管理员」「访问授权」 | 产物 `LICENSE = null`；仓库根目录缺 `license.json`，被 CI 重建洗掉了。补文件后重跑工作流，见 Pages 部署说明第十二节 |
| 停在授权锁屏、没有授权码 | 标签栏「菜单」→「管理员」登录 →「生成授权码」里填入锁屏显示的 4 位设备码 → 生成 16 位绑定码 → 填回激活框；步骤见 Pages 部署说明第十二节 |

**一句话总结**：这个项目的核心不是页面，而是「境外 IP 抓不到 → 境内云函数转发 → 增量合并 → 构建期把数据烤进单文件 HTML → 显式触发 Pages 部署」这条链。页面本身零请求、零后端；链路里任何一环断了，表现都是「页面数据没变」，排查时按第 9 节的顺序逐段定位即可。
